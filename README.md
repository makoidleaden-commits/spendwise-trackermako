# SpendWise

## Project Description
SpendWise is a responsive personal expense tracking web application that allows users to record daily expenses, categorize spending, view real-time totals, and persist their data locally in the browser using `localStorage`.

## Technologies Used
- HTML5
- CSS3 (Custom Properties & Responsive Grid/Flexbox)
- Vanilla JavaScript (DOM Manipulation & LocalStorage API)
- Git & GitHub
- Netlify

## Deployment Process Summary
1. Structured the SpendWise application files (`index.html` and `README.md`) at the root of the project directory in Visual Studio Code.
2. Initialized a local Git repository, committed the project files, and published the repository publicly to GitHub (`makoidleaden-commits/spendwise-trackermako`).
3. Connected the GitHub repository to Netlify and configured automatic deployments from the `main` branch.
4. Customized the default Netlify subdomain to a meaningful project URL (`spendwise-trackermako.netlify.app`).
5. Verified continuous deployment by pushing updates from VS Code to GitHub and confirming Netlify automatically rebuilt and published the live site.

## Challenges Encountered During Deployment
- Initially deployed files manually before linking the GitHub repository directly to Netlify for automated continuous deployment; resolved by connecting the repository in Netlify's Build & Deploy settings.
- Ensuring the full JavaScript logic in `index.html` and all required documentation sections and live URLs in `README.md` were committed and synced cleanly to GitHub.

## Lessons Learned
- How to initialize, commit, and push code directly from Visual Studio Code to a public GitHub repository.
- How continuous deployment (CI/CD) works between GitHub and Netlify so every push to `main` automatically updates the live production website.
- Why verifying the pushed files on GitHub and testing the live URL thoroughly are critical before final submission.
